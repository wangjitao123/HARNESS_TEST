# 知识沉淀技能

## 功能描述

项目交付后，把项目经验、踩坑记录、最佳实践沉淀回仓库，生成经验文档，为后续项目提供参考。不是 AI 凭空判断，是从已有数据里提取。

## 输入参数

| 参数名 | 类型 | 必填 | 描述 | 示例 |
|--------|------|------|------|------|
| project_name | string | 是 | 项目名称 | HIS系统 |
| docs_dir | string | 是 | 项目文档目录（相对路径） | docs |
| backend_dir | string | 否 | 后端项目目录（相对路径） | backend |
| frontend_dir | string | 否 | 前端项目目录（相对路径） | frontend |

## 使用示例

### 示例1：stage-08后触发知识沉淀

```bash
/knowledge-precipitate --project_name "HIS系统" --docs_dir "docs" --backend_dir "backend" --frontend_dir "frontend"
```

### 示例2：独立调用（项目复盘时）

```bash
/knowledge-precipitate --project_name "电商系统" --docs_dir "docs"
```

## 数据来源

| 知识类型 | 来源阶段 | 读取的具体文件 | 怎么来的 |
|---------|---------|---------------|---------|
| **踩坑记录** | stage-07/08 | `dev-loop-log.md`（验证闭环日志） | AI 每次编译失败、测试失败都会记录在这个文件里 |
| **架构经验** | stage-05 | 架构设计文档 + ADR 决策记录 | stage-05 生成的 C4 架构图和技术选型决策 |
| **需求分析经验** | stage-01 | PRD 文档 | stage-01 生成的 PRD 和需求澄清记录 |
| **冲突模式** | cross-review | 交叉评审报告（如有） | PRD↔数据库↔API 一致性检查报告 |
| **最佳实践** | stage-07/08 | 项目代码 | 从生成的代码中提炼可复用的模板和模式 |

## 工作流程

1. **项目经验收集阶段**：从项目各阶段产物中提取经验
   - 读取 stage-07/08 的 `dev-loop-log.md`，提取开发踩坑记录
   - 读取 stage-05 的架构设计文档，提取架构决策经验
   - 读取 stage-01 的 PRD，提取需求分析经验
   - 读取交叉评审报告（如有），提取常见冲突模式

2. **分类整理阶段**：按类型组织知识
   - **架构经验**：技术选型决策、架构模式、设计权衡
   - **踩坑记录**：开发中遇到的问题及解决方案
   - **最佳实践**：可复用的代码模式、设计模式
   - **复用组件清单**：可跨项目复用的组件/模块
   - **交付物索引**：本项目所有产出物清单

3. **知识回写阶段**：追加项目知识沉淀文档（积累模式）
   - **主输出**：追加到 `{docs_dir}/knowledge/项目知识沉淀-{project_name}.md`（如已存在则追加，不存在则新建）
   - **经验存储**：追加到 `{docs_dir}/后端经验-{project_name}.md`（积累后端开发经验）
   - **经验存储**：追加到 `{docs_dir}/前端经验-{project_name}.md`（积累前端开发经验）
   - **追加模式**：每次执行在文档末尾追加 `## 第{N}次沉淀 - {timestamp}` 章节，不覆盖历史内容
   - 首次执行时创建新文档，后续执行时追加

4. **验收阶段**：确认知识沉淀完成
   - 列出所有更新/新建的文件
   - 标注本次新增的内容
   - 向用户确认沉淀内容

## 追加模式说明

知识沉淀采用**追加（积累）模式**，不会覆盖历史经验：

```
首次执行：
  docs/后端经验-HIS系统.md  ← 创建新文件，写入第1次沉淀

第二次执行：
  docs/后端经验-HIS系统.md  ← 在末尾追加「第2次沉淀」章节
  原有内容保留不动！

第三次执行：
  docs/后端经验-HIS系统.md  ← 在末尾追加「第3次沉淀」章节
  ...依此类推，经验越积累越多
```

## 触发时机

- **主流程**：stage-08 完成后，询问用户「是否进行知识沉淀？」
- **独立调用**：项目验收后任意时间，手动执行 `/knowledge-precipitate`

## 自动读取

stage-07、stage-08、stage-09 执行时，**文档同步阶段会自动读取**经验文档，避免重复踩坑：
- stage-07 → 自动读取 `docs/后端经验-{项目}.md`
- stage-08 → 自动读取 `docs/前端经验-{项目}.md`
- stage-09 → 自动读取后端和前端经验文档

> ⚠️ 知识沉淀的前提是前面的阶段已经执行过，产生了 dev-loop-log.md、架构设计文档等产物。如果跳过了一些阶段，对应部分的内容会为空。

## 产出物清单

| 文档 | 路径 | 内容 |
|------|------|------|
| 项目知识沉淀 | `{docs_dir}/knowledge/项目知识沉淀-{project_name}.md` | 踩坑+最佳实践+架构经验+复用组件+交付物索引，5章合一 |
| 后端经验 | `{docs_dir}/后端经验-{project_name}.md` | 后端开发踩坑和解决方案 |
| 前端经验 | `{docs_dir}/前端经验-{project_name}.md` | 前端开发踩坑和解决方案 |

## 注意事项

1. **不修改业务代码**：知识沉淀只生成文档，不修改项目业务代码
2. **追加模式，不覆盖**：每次执行追加到已有文档末尾，历史经验不会丢失
3. **主输出是单文件**：`docs/knowledge/项目知识沉淀-{project_name}.md`，所有内容集中在一个文档
4. **经验独立存储**：后端经验存 `docs/后端经验.md`，前端经验存 `docs/前端经验.md`
5. **AI 提炼而非堆砌**：从 dev-loop-log 中提炼有价值的模式，不是简单复制日志
