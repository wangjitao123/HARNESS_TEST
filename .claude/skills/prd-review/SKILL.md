# PRD 交互式评审技能

## 功能描述

读取 stage-01 产出的 PRD 文档，从多个维度进行 AI 评审，**逐条向用户提出发现的问题**，用户回答"对"（问题成立）或"错"（AI误判），最终生成一份包含用户确认结果的评审报告。

## 输入参数

| 参数名 | 类型 | 必填 | 描述 | 示例 |
|--------|------|------|------|------|
| prd_doc | string | 是 | PRD文档路径（相对路径） | docs/需求分析/PRD-HIS系统.md |
| output_dir | string | 否 | 评审报告输出目录（不传默认与PRD同目录） | docs/需求分析 |
| review_depth | string | 否 | 评审深度：quick（快速）/ standard（标准）/ deep（深度） | standard |

## 使用示例

### 示例1：评审stage-01产出的PRD

```bash
/prd-review --prd_doc "docs/需求分析/PRD-HIS系统.md"
```

### 示例2：深度评审

```bash
/prd-review --prd_doc "docs/需求分析/PRD-HIS系统.md" --review_depth "deep" --output_dir "docs/需求分析"
```

## 交互式评审流程

### 第一步：加载PRD文档

1. 读取 `prd_doc` 指定的 PRD 文档
2. 提取以下关键信息：
   - 需求概述
   - 用户故事列表
   - 功能需求清单（含RICE评分）
   - 非功能需求
   - 待澄清问题清单
3. 向用户展示 PRD 摘要，确认文档内容正确加载

### 第二步：AI多维度评审

从以下维度分析 PRD，识别潜在问题：

**维度1：需求完整性**
- 是否有业务场景未被覆盖
- 是否遗漏了关键用户角色
- 异常流程是否有描述

**维度2：需求一致性**
- 用户故事之间是否有矛盾
- 功能需求与用户故事是否对应
- RICE评分是否合理（Reach/Impact/Confidence/Effort 各项是否有明显不合理）

**维度3：验收标准**
- 验收标准是否可测试
- 是否遗漏了边界场景
- 是否有歧义表述

**维度4：实体与角色**
- 关键业务实体是否全部识别
- 用户角色权限是否清晰
- 实体间关系是否明确

**维度5：非功能需求**
- 性能指标是否量化
- 安全需求是否具体
- 可用性是否有明确SLA

**维度6：可行性预判**
- 是否存在技术实现难度过高的功能
- 是否存在功能依赖但未标注依赖关系
- 是否存在明显的前后矛盾

### 第三步：逐条交互确认（核心环节）

**对每个发现的问题，按以下格式与用户交互：**

```
---
问题 #1
维度：需求完整性
严重程度：⚠️ 中
问题描述：
  PRD中定义了"患者挂号"功能，但未描述"挂号退号"的异常流程。
  如果患者挂号后需要取消，应该如何处理？

AI建议：
  建议补充"挂号退号"的用户故事和验收标准。

请确认：这个问题是否成立？
  回答"对" = 问题成立，需要修改
  回答"错" = AI误判，不需要修改
  回答"跳过" = 暂不决定，标记为待讨论
---
```

**交互规则：**
1. **每次只提出一个问题**，等待用户回答后再提出下一个
2. 用户回答"对"：记录为"已确认问题"，纳入修改清单
3. 用户回答"错"：记录为"已排除问题"，附上AI的原始判断但标记为用户排除
4. 用户回答"跳过"：记录为"待讨论问题"
5. 用户可以随时回答"结束"提前终止评审
6. 全部问题提出完毕后，进入报告生成阶段

### 第四步：生成评审报告

根据用户确认结果，生成评审报告：

```markdown
# PRD 评审报告

## 评审概要
- 项目名称：{project_name}
- PRD文档：{prd_doc_path}
- 评审时间：{timestamp}
- 评审深度：{review_depth}
- 评审结论：✅ 通过 / ⚠️ 有条件通过 / ❌ 不通过

## 评审统计
| 维度 | 提出问题数 | 已确认 | 已排除 | 待讨论 |
|------|-----------|--------|--------|--------|

## 已确认问题（需修改）
### 问题1：{标题}
- 维度：{dimension}
- 严重程度：🔴高/🟠中/🟢低
- 描述：{description}
- AI建议：{suggestion}

## 已排除问题（AI误判）
### 问题1：{标题}
- 维度：{dimension}
- AI判断：{ai_reasoning}
- 用户说明：{user_note or "未说明"}

## 待讨论问题
### 问题1：{标题}
- 维度：{dimension}
- 描述：{description}
- 说明：{note}

## 评审结论
### 总体评价
{综合评价}

### 建议措施
1. {suggestion_1}
2. {suggestion_2}

### 下一步
- [ ] 修改已确认问题
- [ ] 讨论待确认问题
- [ ] 修改完成后重新评审
```

## 评审深度说明

| 深度 | 维度覆盖 | 交互方式 | 适用场景 |
|------|---------|---------|---------|
| quick | 完整性 + 一致性 | 只提出🔴高严重度问题 | 简单项目快速过审 |
| standard | 完整性 + 一致性 + 验收标准 + 实体角色 | 提出🔴+🟠问题 | 中等规模项目（默认） |
| deep | 全部6个维度 | 提出全部问题 | 复杂项目深度评审 |

## 产出物清单

| 文档名称 | 文件格式 | 存放路径 |
|---------|---------|---------|
| PRD评审报告 | .md | {output_dir}/PRD评审报告-{timestamp}.md |

## 注意事项

1. **逐条交互**：必须一次只提一个问题，等用户回答后再提下一个，不能一次性列出所有问题
2. **用户可随时退出**：用户回答"结束"时立即终止，已确认的问题仍纳入报告
3. **评审报告必须归档**：评审报告存放在PRD同目录，作为后续修改的依据
4. **不修改PRD原文**：评审只产出报告，不直接修改PRD文档，修改由用户决定
5. **AI建议仅供参考**：每条问题的"AI建议"只是参考，用户有权否决
