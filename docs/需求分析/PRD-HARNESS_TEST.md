## 1. 需求概述

### 1.1 需求背景

随着移动互联网的普及，在线阅读已成为用户获取小说内容的主要方式。起点中文网、番茄小说、微信读书等平台拥有数亿用户，验证了在线小说阅读市场的巨大潜力。当前市场上主要存在两类平台：付费订阅型（起点、掌阅）和免费+广告型（番茄小说），用户对优质阅读体验的需求持续增长。

本项目旨在构建一个功能完善、体验优良的小说阅读网站，提供从发现、浏览、阅读到管理的全流程服务。

### 1.2 需求目标

| 目标类型 | 目标描述 | 衡量指标 |
|---------|---------|---------|
| 业务目标 | 搭建小说阅读平台，吸引用户并建立阅读生态 | 月活用户 ≥ 10万（上线3个月） |
| 用户目标 | 提供流畅、沉浸式的小说阅读体验 | 用户平均阅读时长 ≥ 30分钟/天 |
| 产品目标 | 覆盖小说阅读全链路核心功能 | 核心功能完成率 100% |

### 1.3 预期收益

- **直接收益**：通过VIP订阅、付费章节、广告收入实现商业化（付费阅读与会员体系计划纳入 V1.2 之后版本，MVP 阶段暂不实现）
- **间接收益**：积累用户阅读数据，构建个性化推荐能力，提升用户留存

### 1.4 原型参考

已生成可交互前端原型，覆盖首页、分类、书架、详情、阅读器、用户中心六大核心页面。
原型路径：`docs/需求分析/prototype/index.html`

## 2. 用户分析

### 2.1 目标用户

| 用户角色 | 用户特征 | 使用场景 | 占比 |
|---------|---------|---------|------|
| 普通读者 | 小说爱好者，每天阅读1-3小时，关注阅读体验 | 发现小说、阅读、收藏、评论 | 85% |
| 重度读者 | 追更狂人，同时追读多本书，关注更新速度 | 追更、多书管理、离线阅读 | 10% |
| 作者/创作者 | 创作小说内容，关注读者反馈和数据 | 发布章节、查看数据、互动 | 3% |
| 平台管理员 | 内容审核、用户管理、数据监控 | 内容管理、用户管理、运营 | 2% |

### 2.2 用户痛点

| 痛点编号 | 痛点描述 | 影响程度 | 当前解决方案 |
|---------|---------|---------|------------|
| P1 | 阅读体验差（字体小、无夜间模式、翻页卡顿） | 高 | 用户忍受或换平台 |
| P2 | 找不到想看的书（分类不清晰、搜索不准确） | 高 | 多平台切换搜索 |
| P3 | 追更管理困难（多本书同时追，忘记看到哪章） | 中 | 手动记录或使用书签 |
| P4 | 阅读疲劳（长时间阅读眼睛不适） | 中 | 自行调整屏幕亮度 |
| P5 | 无个性化推荐（新书发现效率低） | 中 | 靠朋友推荐或排行榜 |

### 3.2 功能详情

#### F-001: 首页推荐

**功能描述**：作为用户进入网站的第一入口，展示推荐内容，引导用户发现和阅读小说。

**功能组成**：
- Hero Banner：轮播展示热门小说推荐
- 热门推荐区：按热度排序展示小说卡片
- 最近更新区：展示最新更新的连载小说
- 完本精选区：展示已完结的高评分小说

**业务规则**：
- BR-001：热门推荐按热度值降序排列，每小时更新
- BR-002：最近更新区展示24小时内更新的小说
- BR-003：完本精选区展示评分≥8.0的已完结小说
- BR-004：每区最多展示6本，点击"更多"进入分类页

**边界条件**：
- 小说数量不足6本时，展示全部可用小说
- 无小说数据时，展示空状态引导文案

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 数据加载失败 | 展示缓存数据 | "加载失败，请刷新重试" |
| 网络超时 | 3次重试后降级展示 | "网络异常，部分内容加载失败" |

#### F-002: 分类浏览

**功能描述**：用户可按分类和排序方式浏览小说列表。

**分类标签**：玄幻、修真、都市、言情、科幻、悬疑、历史、军事、网游

**排序方式**：最热（按热度）、最新（按更新时间）、好评（按评分）、字数（按总字数）

**业务规则**：
- BR-005：默认选中"全部"分类 + "最热"排序
- BR-006：切换分类时保持当前排序方式
- BR-007：小说列表支持无限滚动分页加载

#### F-003: 小说阅读器（核心功能）

**功能描述**：提供沉浸式的小说阅读体验，是产品的核心体验模块。

**功能组成**：
- 阅读正文：清晰排版，适合长时间阅读
- 字号调整：A+/A-按钮，支持14-32px范围
- 主题切换：日间模式（浅米色）、夜间模式（深色）、护眼模式（暖黄）
- 上下章导航：上一章/下一章按钮 + 章节进度显示
- 阅读设置面板：字号预设、主题选择
- 书签：添加/移除书签标记
- 键盘快捷键：← → 键翻章

**业务规则**：
- BR-008：阅读设置（字号、主题）保存到本地存储，用户下次访问自动应用
- BR-009：阅读进度自动保存，退出后可从上次位置继续阅读
- BR-010：章节内容预加载下一章，减少等待时间

**交互流程**：
```
打开章节 → 加载内容 → 展示阅读界面
                           ├→ 调整字号 → 实时更新字体大小
                           ├→ 切换主题 → 更新背景色和文字色
                           ├→ 添书签 → 保存当前章节位置
                           ├→ 上一章 → 加载前一章内容
                           └→ 下一章 → 加载后一章内容
```

**边界条件**：
- 第一章时"上一章"按钮禁用
- 最后一章时"下一章"按钮禁用
- 字号最小值14px，最大值32px

#### F-004: 小说详情页

**功能描述**：小说信息展示页，用户可了解小说详情并开始阅读。

**页面组成**：
- 封面图：展示小说封面
- 基本信息：标题、作者、字数、状态、评分、热度
- 标签：小说分类标签
- 简介：小说内容简介（默认折叠3行）
- 操作按钮：开始阅读、加入书架、分享
- 章节目录：显示章节列表（默认展示前20章）
- 评论Tab：读者评论列表
- 信息Tab：作品详细信息

**业务规则**：
- BR-011：点击"开始阅读"跳转到第一章节（或上次阅读位置）
- BR-012：点击"加入书架"将小说加入用户书架
- BR-013：章节列表支持展开全部章节

#### F-005: 书架管理

**功能描述**：用户管理收藏和阅读中的小说。

**功能组成**：
- 正在阅读：展示有阅读进度的小说，显示进度条
- 我的收藏：展示用户收藏的所有小说
- 阅读历史：作为书架的子模块，展示近期阅读过的小说，按时间倒序排列，支持清除

**业务规则**：
- BR-014：阅读进度以百分比+当前章节号展示
- BR-015：点击小说卡片进入详情页
- BR-016：阅读历史按时间倒序排列

#### F-006: 用户注册/登录

**功能描述**：用户账号管理，支持注册、登录、个人中心。

**功能组成**：
- 注册：手机号/邮箱注册，用户名设置
- 登录：手机号/邮箱+密码登录，支持"记住我"
- 个人中心：用户信息、阅读统计、功能入口

**业务规则**：
- BR-017：密码长度6-20位，包含字母和数字
- BR-018：连续登录失败5次锁定30分钟
- BR-019：登录态有效期7天（勾选"记住我"为30天）

#### F-007: 搜索功能

**功能描述**：支持用户搜索小说、作者、标签。

**业务规则**：
- BR-020：支持模糊搜索，匹配标题、作者名、标签
- BR-021：搜索结果按相关度排序
- BR-022：未输入关键词时点击搜索，提示“请输入搜索关键词”；搜索结果为空时，提示“未找到相关小说，换个词试试”

#### F-016: 后台管理

**功能描述**：为平台管理员提供内容审核、用户管理、数据监控的后台入口，承载平台管理员角色的核心职责。

**功能组成**：
- 内容审核：小说/章节/评论的审核、下架、删除
- 用户管理：用户状态管理、角色调整、账号封禁/解封
- 数据监控：基础运营数据看板，如日活、新增用户数、内容发布量

**业务规则**：
- BR-041：管理员可查看并审核待发布的小说/章节
- BR-042：管理员可对违规评论进行下架或删除
- BR-043：管理员可调整用户角色（reader/author/admin），但不可修改自己的角色
- BR-044：数据看板展示最近 7 天的核心运营指标

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 测试方法 |
|------|------|---------|
| 首页加载时间 | < 2秒 | Lighthouse性能测试 |
| 章节加载时间 | < 500ms | 接口响应时间监控 |
| 翻章响应时间 | < 200ms | 用户操作到页面渲染完成 |
| 并发用户数 | ≥ 1000 | 压力测试 |
| 页面大小 | 首屏 < 500KB | 资源体积分析 |

### 4.2 安全需求

- 认证要求：JWT Token认证，支持refresh token续期
- 权限控制：RBAC角色权限（读者/作者/管理员）
- 数据安全：用户密码bcrypt加密存储，敏感数据传输HTTPS加密
- 内容保护：章节内容防爬虫（频率限制、验证码）
- API安全：接口限流、SQL注入防护、XSS过滤

### 4.3 兼容性需求

- 浏览器：Chrome 90+、Firefox 90+、Safari 14+、Edge 90+
- 设备：PC（≥1024px）、平板（768-1023px）、手机（320-767px）
- 系统：Windows 10+、macOS 11+、iOS 14+、Android 10+

### 4.4 可用性需求

- 阅读器字体大小范围14-32px，支持连续调节
- 三种阅读主题（日间/夜间/护眼），一键切换
- 键盘快捷键支持（← → 翻页）
- 响应式布局，适配多端
- 操作反馈：加载状态、成功/失败提示

### 5.3 导航设计

- **PC端**：顶部固定导航栏（Logo + 搜索框 + 书架/主题/用户图标）
- **移动端**：顶部导航栏 + 底部Tab导航（首页/分类/书架/我的）
- **全局导航**：Logo点击返回首页，搜索框始终可见
- **上下文导航**：阅读器内有独立的章节导航栏

### 6.2 数据验证规则

- 用户名：2-20个字符，支持中英文数字下划线
- 密码：6-20位，须包含字母和数字
- 邮箱：符合RFC 5322标准格式
- 手机号：中国大陆11位手机号格式
- 章节内容：最短500字，最长50,000字
- 评论内容：最短1字，最长2000字
- 评分：1-5整数

### 6.3 核心字段计算规则

#### 小说平均评分（novels.rating）

- `novels.rating` = 该小说所有有效评论评分的算术平均值
- 仅统计 `comments.rating` 不为 NULL 的评论
- 新评分提交或评论变更后，系统准实时更新该值
- 保留一位小数

**示例**：某小说收到 3 条评论，评分分别为 4、5、4，则 `novels.rating` = (4+5+4)/3 ≈ 4.3
