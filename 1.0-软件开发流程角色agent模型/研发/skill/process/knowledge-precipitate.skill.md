# Skill: knowledge-precipitate（知识沉淀）

## 基本信息

- **ID**: knowledge-precipitate
- **名称**: 知识沉淀
- **版本**: 1.0.0
- **分类**: process
- **部门**: 研发部
- **优先级**: P2
- **描述**: 项目交付后，把项目经验、踩坑记录、最佳实践沉淀回仓库，更新CLAUDE.md和知识库，为后续项目提供参考。

## 触发条件

- **命令**: `/knowledge-precipitate`
- **关键词**: 知识沉淀, 经验总结, 沉淀知识, 项目复盘, 经验回写
- **patterns**: 
  - 沉淀.*经验
  - 总结.*项目
  - 复盘.*经验

## 输入参数

| 参数名 | 类型 | 必填 | 描述 | 示例 |
|--------|------|------|------|------|
| project_name | string | 是 | 项目名称 | HIS系统 |
| docs_dir | string | 是 | 项目文档目录（相对路径） | docs |
| output_dir | string | 否 | 知识库目录（默认 docs/knowledge） | docs/knowledge |
| backend_dir | string | 否 | 后端项目目录 | backend |
| frontend_dir | string | 否 | 前端项目目录 | frontend |

## 工作流程

1. **项目经验收集阶段**：从项目各阶段产物中提取经验
   - 读取 stage-07 的 dev-loop-log.md，提取开发踩坑记录
   - 读取 stage-05 的设计文档，提取架构决策经验
   - 读取 stage-01 的 PRD，提取需求分析经验
   - 读取交叉评审报告（如有），提取常见冲突模式

2. **分类整理阶段**：按类型组织知识
   - **架构经验**：技术选型决策、架构模式、设计权衡
   - **踩坑记录**：开发中遇到的问题及解决方案
   - **最佳实践**：可复用的代码模式、设计模式
   - **复用组件清单**：可跨项目复用的组件/模块
   - **交付物索引**：本项目所有产出物清单

3. **知识回写阶段**：追加项目知识沉淀文档（积累模式）
   - **主输出**：追加到 `docs/knowledge/项目知识沉淀-{project_name}.md`（如已存在则追加，不存在则新建）
   - **经验存储**：追加到 `docs/后端经验-{project_name}.md`（积累后端开发经验）
   - **经验存储**：追加到 `docs/前端经验-{project_name}.md`（积累前端开发经验）
   - **追加模式**：每次执行在文档末尾追加 `## 第{N}次沉淀 - {timestamp}` 章节，不覆盖历史内容
   - 首次执行时创建新文档，后续执行时追加

4. **验收阶段**：确认知识沉淀完成
   - 列出所有更新/新建的文件
   - 标注本次新增的内容
   - 向用户确认沉淀内容

## 追加模式说明

知识沉淀采用**追加（积累）模式**，不会覆盖历史经验：

```
首次执行：
  docs/后端经验-HIS系统.md  ← 创建新文件，写入第1次沉淀

第二次执行：
  docs/后端经验-HIS系统.md  ← 在末尾追加「第2次沉淀」章节
  原有内容保留不动！

第三次执行：
  docs/后端经验-HIS系统.md  ← 在末尾追加「第3次沉淀」章节
  ...依此类推，经验越积累越多
```

每次追加的章节格式：
```markdown
## 第{N}次沉淀 - {timestamp}

### 本次踩坑记录
（本次新发现的坑）

### 本次最佳实践
（本次新总结的实践）
```

## 沉淀内容分类

### 1. 架构经验
从 stage-05 的架构设计文档和 ADR 中提取：
- 技术选型决策（为什么选Spring Boot而不是其他）
- 架构模式（分层架构、微服务、单体）
- 设计权衡（性能vs可维护性、简单vs灵活）
- 关键约束（多租户、审计追踪、逻辑删除）

### 2. 踩坑记录
从 stage-07 的 dev-loop-log.md 中提取：
- 编译错误模式及解决方案
- 测试失败原因及修复方法
- 接口设计问题及修正
- 数据库设计陷阱及避免方法

### 3. 最佳实践
从项目代码和文档中提炼：
- 可复用的代码模板
- 命名规范实践
- API设计规范实践
- 数据库设计规范实践

### 4. 复用组件清单
识别项目中可跨项目复用的组件：
- 通用工具类
- 通用Controller/Service基类
- 通用前端组件
- 通用配置模板

### 5. 交付物索引
建立本项目所有产出物的索引：
- 文档清单（PRD、BRD、架构设计、数据库设计、API文档、排期计划）
- 代码清单（实体类、Mapper、Service、Controller、VO）
- 脚本清单（DDL、数据迁移、测试脚本）

## 注意事项

1. **不修改业务代码**：知识沉淀只生成文档，不修改项目业务代码
2. **追加模式，不覆盖**：每次执行追加到已有文档末尾，历史经验不会丢失
3. **主输出是单文件**：`docs/knowledge/项目知识沉淀-{project_name}.md`，所有内容集中在一个文档
4. **经验独立存储**：后端经验存 `docs/后端经验.md`，前端经验存 `docs/前端经验.md`
5. **AI 提炼而非堆砌**：从 dev-loop-log 中提炼有价值的模式，不是简单复制日志
6. **stage-07/08/09 自动读取**：执行 stage-07/08/09 时，AI 会自动读取经验文档，避免重复踩坑
